PantryPal approved design implementation - 13 October 2026

Implemented
- Shared forest/cream desktop shell, local fonts, code-native navigation icons,
  clear primary/secondary/destructive actions, focus styles and responsive layouts.
- Week agenda, explicit meal selection/day/servings/Add, occurrence actions,
  cooked-event history and readable scaling summaries.
- Meal catalogue filters/cards, two-column recipe detail, grouped recipe editor,
  household field management and ingredient matching disclosures.
- Ingredient catalogue/editor, aliases, conversion rules and vocabulary management.
- Shopping rows, generated-quantity basis in amount editing, provenance/warnings,
  excluded-item review and explicit reset confirmation.
- Task-based settings with mounted drafts, unit convention references,
  browser session reset, staged backup restore and update controls.
- Import Source/Review/Save, manual fallback, raw quantities and review/duplicate
  acknowledgement before save.
- Unsaved edit guards for navigation and cancellation; pending writes block leaving.

remain the baseline. No dependencies, remote fonts or production image assets

Optional isolated review runner (never opens the household database)
  npm run build
  cargo run --example ui_review --features tauri/custom-protocol -- YYYY-MM-DD
Run Cargo from the repository workspace with the development environment loaded.
Replace YYYY-MM-DD with the desired local date. Each launch creates a fresh
.verification/ui-review-UUID database and dedicated recipe-browser profile.
Close the runner before rebuilding examples on Windows to avoid executable locks.
